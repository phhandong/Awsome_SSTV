# CPLL 输出 → freq_to_pixel 输入的数据流分析

> 基于静态分析推导  
> 日期: 2026-08-06

---

## 问题陈述

从静态分析已确认：
- **CPLL::DemodSample 输出**: `-(error × 0.0025 × 16384)` 范围 `[-16384, +16384]`
- **freq_to_pixel 输入**: 范围 `[23552, 36864]` (DC 校正前为 `[23680, 36992]`)

两者数值范围不匹配，说明中间存在未定位的转换环节。

---

## 数学推导

### 1. CPLL 输出范围

```python
# SSTV 频率范围
freq_black = 1500 Hz  # 黑色
freq_white = 2300 Hz  # 白色
center_freq = 1900 Hz # PLL 中心

# CPLL 计算
error_black = 1900 - 1500 = +400 Hz
error_white = 1900 - 2300 = -400 Hz

cpll_out_black = -(400 × 0.0025 × 16384) = -16384
cpll_out_white = -(-400 × 0.0025 × 16384) = +16384
```

**CPLL 输出范围**: `[-16384, +16384]`

### 2. freq_to_pixel 输入范围

从 RVA 0x1cf7c 反汇编确认：
- DC 校正: `adjusted = input - 128`
- 有效范围检查: `adjusted ∈ [23552, 36864]`
- 因此输入范围: `[23680, 36992]` (加回 DC 偏移)

### 3. 线性转换推导

从 CPLL 输出映射到 pixel 输入需要线性变换：

```
pixel_input = a × cpll_out + b
```

其中：
- `a = (36992 - 23680) / (16384 - (-16384)) = 13312 / 32768 = 0.40625 = 13/32`
- `b = 23680 - 0.40625 × (-16384) = 30336`

**转换公式**:
```
pixel_input = 0.40625 × cpll_out + 30336
            = (13/32) × cpll_out + 30336
```

验证：
- 黑色: `0.40625 × (-16384) + 30336 = 23680` ✓
- 白色: `0.40625 × 16384 + 30336 = 36992` ✓

## 转换实现的可能位置

### 假设 1: 积分器 + 缩放器

CPLL 输出可能经过：
1. **积分器**: 将频率偏移累积为相位
   ```c
   phase_accumulator += cpll_out × (13.0 / 32.0)
   ```

2. **偏移**: 添加基准值
   ```c
   pixel_input = phase_accumulator + 30336
   ```

### 假设 2: 直接缩放转换

在 DoJob 主循环 (RVA 0xd880) 中，CPLL 输出与 freq_to_pixel 输入之间可能有：

```c
// 未定位的转换函数 (RVA 未知)
double cpll_to_pixel_input(double cpll_out) {
    // 方法 A: 定点运算
    int32_t scaled = (int32_t)(cpll_out * 13);  // 乘以 13
    scaled = (scaled >> 5);                      // 除以 32 (右移 5)
    return (double)(scaled + 30336);
    
    // 方法 B: 浮点运算
    // return cpll_out * 0.40625 + 30336.0;
}
```

### 假设 3: 查找表 (LUT)

CPLL 输出可能通过查找表映射：
- 输入: CPLL 输出 `[-16384, +16384]` 离散化为整数索引
- 输出: 预计算的 pixel_input 值
- LUT 大小: `32768 × 8 bytes = 256 KB`

可能的数据段地址 (未确认):
- `.data` 段中的大数组
- 或运行时动态生成

## 常数 28672 的作用

从 freq_to_pixel 公式:
```c
pixel = ftol((28672 - smoothed_value) × 0.0244140625)
```

其中 `28672 = 7 × 4096 = 7 × 2^12`

**分析**:
- `smoothed_value` 中心值应为 `30336` (pixel_input 中心)
- `28672 - 30336 = -1664` (负值)
- 映射到像素: `-1664 × 0.0244140625 ≈ -40`

这表明：
1. **input 不是频率值**，而是某种**归一化相位或样本计数**
2. `28672` 是**参考中心**，用于计算相对偏移
3. 实际像素范围可能是 `[-128, +127]` (有符号) 或需要额外偏移

**已确认**:
- CPLL 输出范围: `[-16384, +16384]`
